# MochiPrep agent guide

Local-first, BYOK AI trading terminal for USDT-margined crypto perpetuals. Agents trade paper accounts,
OKX Demo Trading, or real OKX accounts. OKX is the only exchange; every other venue is a roadmap milestone.

## Layout

The backend is Rust. Node is only for the web UI and the scripts.

- `packages/shared`: domain types, Zod schemas, indicators. The API contract the web UI uses.
- `apps/web`: React UI.
- `crates/mochi-decimal`, `mochi-domain`: decimal math and domain types, instrument specs.
- `crates/mochi-core`: perp math, fill model, risk engine, paper engine, ledger audit.
- `crates/mochi-store`: SQLite store and migrations (`crates/mochi-store/migrations/`).
- `crates/mochi-vault`: master-password crypto.
- `crates/mochi-market`: OKX public feed, deterministic replay tape, news.
- `crates/mochi-ai`: mock and remote providers, prompts, indicators, secret redaction.
- `crates/mochi-okx`: signed OKX client and `OkxEngine`, plus a fake OKX for tests behind the `fake` feature. Real money: see docs/OKX_TRADING.md.
- `crates/mochi-server`: HTTP routes (axum), SSE `/api/events`, the `Runtime` actor, agent cycle, embedded web UI.
- `crates/mochi-launcher-core`, `crates/mochi-launcher`: the desktop launcher (settings, import, tray model, backend supervisor, updater; Tauri shell). See docs/LAUNCHER.md.
- `crates/golden`: frozen fixtures generated by the former Node backend. Rust tests read them. Do not regenerate them; `rust-vault.json` is the exception, written by Rust with `MOCHI_UPDATE_GOLDEN=1 cargo test -p mochi-vault`.

## Commands

    pnpm install
    pnpm dev                  # Rust server (cargo) plus vite; MOCHIPREP_PORT, MOCHIPREP_WEB_PORT
    pnpm build                # web UI, which mochi-server embeds
    pnpm start                # build, then cargo run --release -p mochi-server
    pnpm test                 # vitest, apps/web
    pnpm typecheck
    pnpm test:e2e             # Playwright against the release mochi-server (MOCHIPREP_E2E_API_PORT, default 8877); needs Chrome
    cargo test --workspace    # Rust crates; on Linux mochi-launcher needs libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev (or add --exclude mochi-launcher)
    pnpm bundle -- --target <triple>   # installers
    pnpm measure:memory       # memory gate, see README

Needs Node >= 22.13 and a Rust toolchain. Workspace packages export TypeScript source, so web tests, typecheck and `dev` need no build step.

## Notes

- `mochi-server` serves the Node-era API contract: auth, SSE, paper trading, replay, market data, instruments, news, AI providers, agents, suggestions, demo mode, the master-password vault and OKX trading. It embeds `apps/web/dist`, so `pnpm build` first if you run it by hand.
- OKX has only been run against the in-process fake OKX, never OKX Demo or a real account. The UNCONFIRMED list in `docs/OKX_TRADING.md` is the owner's recommended check before trusting real money (the owner decided on 2026-11-16 that it is not a release condition).
- `MOCHIPREP_OFFLINE=1`: no OKX public feed and no news fetching (the replay still runs). The e2e config sets it.
- Releases: a `vX.Y.Z` tag matching `[workspace.package].version` runs `.github/workflows/release.yml`, which builds a DRAFT release; the owner publishes. Builds are not OS code-signed; updater artifacts are signed.
- Performance statistics (`performance.rs`), fractions and times use `f64` or integers by design; money never does.
- The vault format stays byte-compatible with the golden fixtures in `crates/golden`. Migrations live in `crates/mochi-store/migrations/`.
- Rust doc comments that name `packages/...` or `apps/server/...` refer to the Node backend, removed in the switch-over and still in git history.

## Rules that must not bend

- Accounting uses `mochi_decimal::Dec` (`crates/mochi-decimal`), never `f64` or `rust_decimal`.
- Every wallet or margin change goes through the ledger, inside one store transaction.
- AI output is untrusted. Only the agent cycle (`crates/mochi-server/src/runtime/agent_cycle.rs`) turns it into orders, and only after strict parsing (`agent_parse.rs`) and the risk engine.
- The paper engine must never invent a price: fills come from observed quotes, never OHLC paths.
- AI keys live in SQLite by the owner's choice, and never in logs, errors or the browser. With a master password set they are only stored sealed (`crates/mochi-vault`).
- OKX credentials stay in `Runtime` memory (`crates/mochi-server/src/runtime`), unless the owner opts to save them sealed by the master password. Never write them to disk in plaintext or show them to a model. The master password and data key are never written anywhere.
- Unlocking reconnects saved OKX keys through the full connect checks and never arms: arming always takes the typed phrase.
- Never resend an order after an unknown outcome: resolve it by lookup. Every OKX order passes `pre_trade_refusal` (`crates/mochi-okx/src/engine/refusal.rs`).
- Contract specs come from OKX, never from guesses. A symbol is open-ended: look it up in the instrument registry (`crates/mochi-domain/src/registry.rs`), and remember replay has only `DEFAULT_SYMBOLS`.
- A key that can withdraw is always refused. Exits stay possible when disarmed.
- Never present simulated results as predictive, and never claim an unimplemented feature works.
- Comments explain why. Do not add placeholder code for future markets.
