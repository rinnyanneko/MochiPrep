# MochiPrep agent guide

Local-first, BYOK AI trading terminal for USDT-margined crypto perpetuals. Agents trade paper accounts,
OKX Demo Trading, or real OKX accounts. OKX is the only exchange; every other venue is a roadmap milestone.

## Layout

- `packages/shared`: domain types, Zod schemas, indicators. The API contract lives here.
- `packages/core`: decimal helpers, perp math, fill model, risk engine, paper engine, ledger audit.
- `packages/market-data`: `MarketDataProvider`, OKX public adapter, deterministic replay tape.
- `packages/ai-providers`: mock, OpenAI-compatible, OpenAI, Anthropic, Gemini, secret redaction.
- `packages/agents`: prompt, output parsing, `AgentRunner` cycle.
- `packages/exchanges`: signed OKX client and `OkxExecutionEngine`. Real money: see docs/OKX_TRADING.md.
- `crates`: Rust backend port (in progress); see the Rust section below.
- `apps/server`: Fastify routes, `Runtime`, SQLite store and migrations.
- `apps/web`: React UI.

## Commands

    pnpm install
    pnpm test                 # vitest, all packages, network blocked
    pnpm typecheck
    pnpm test:e2e             # Playwright, needs Chrome
    cargo test --workspace    # Rust crates
    pnpm golden               # regenerate crates/golden from the TypeScript code

Needs Node >= 22.13 (`node:sqlite`). Workspace packages export TypeScript source, so tests, typecheck and `dev` need no build step. `start` bundles the server with esbuild (`apps/server/build.mjs`) to avoid tsx's memory cost; anything the server reads from disk at runtime must be copied into `dist/` there, as migrations are.

## Rust backend (in progress)

- Crates live under `crates/`: `mochi-domain`, `mochi-store`, `mochi-vault`, `mochi-market`. There is no Rust server, runtime, agents or OKX trading yet; the Node backend is still what runs.
- `crates/golden` holds fixtures generated by `apps/server/golden/generate.ts`, except `rust-vault.json`, which Rust writes with `MOCHI_UPDATE_GOLDEN=1 cargo test -p mochi-vault`. The Rust tests read them, and `apps/server/test/golden.test.ts` fails when one is stale.
- `pnpm golden` skips randomized fixtures (`vault.json`, `node-created.sqlite`) that already exist; pass `--all` to rewrite them.
- A TypeScript change that alters a golden file must regenerate it (`pnpm golden`) and keep the Rust port in step.
- Migrations stay in `apps/server/src/db/migrations/`; Rust embeds the same files. The vault format must stay byte-compatible in both directions.

## Rules that must not bend

- Accounting uses `D` from `packages/core/src/decimal.ts`, never JS number arithmetic.
- Every wallet or margin change goes through the ledger, inside one store transaction.
- AI output is untrusted. Only `AgentRunner` turns it into orders, and only after Zod and the risk engine.
- The paper engine must never invent a price: fills come from observed quotes, never OHLC paths.
- AI keys live in SQLite by the owner's choice, and never in logs, errors or the browser. With a master password set they are only stored sealed (`apps/server/src/vault.ts`).
- OKX credentials stay in `Runtime` memory, unless the owner opts to save them sealed by the master password. Never write them to disk in plaintext or show them to a model. The master password and data key are never written anywhere.
- Unlocking reconnects saved OKX keys through the full connect checks and never arms: arming always takes the typed phrase.
- Never resend an order after an unknown outcome: resolve it by lookup. Every OKX order passes `preTradeRefusal`.
- Contract specs come from OKX, never from guesses. `SymbolId` is open-ended: use `getInstrument`, and remember replay has only `DEFAULT_SYMBOLS`.
- A key that can withdraw is always refused. Exits stay possible when disarmed.
- Never present simulated results as predictive, and never claim an unimplemented feature works.
- Comments explain why. Do not add placeholder code for future markets.
