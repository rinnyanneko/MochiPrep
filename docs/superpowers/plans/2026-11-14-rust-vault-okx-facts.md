## 1. Node vault runtime

### 1.1 `apps/server/src/vault.ts` (79 lines)

- `KdfParams { N, r, p }` (vault.ts:9-13). `DEFAULT_KDF = { N: 2 ** 17, r: 8, p: 1 }` (16). `PasswordWrap { salt, kdf, wrappedKey }` (18-22).
- `class WrongPasswordError extends Error`, message exactly `Wrong master password` (24-28). The only vault-specific error class.
- Constants: `VERSION = 'v1'` (30), `WRAP_CONTEXT = 'mochiprep:vault-key'` (31).
- `derive(password, salt, kdf)` (33-38, private): async scrypt, key length 32, `password.normalize('NFC')`, options `{...kdf, maxmem: 256 * kdf.N * kdf.r}`. Node scrypt throws on N not a power of two or bad r/p (raw Node error, not caught anywhere).
- `seal(key: Buffer, plaintext, context): string` (44-50): AES-256-GCM, 12-byte random IV, `setAAD(Buffer.from(context))`; output `"v1." + b64(iv) + "." + b64(tag) + "." + b64(body)` (standard base64 with padding, 4 `.`-joined parts, 16-byte tag).
- `open(key, sealed, context): string` (52-59): `sealed.split('.')`, destructures the first four parts (extra parts ignored); throws `Error('Unrecognized sealed value')` when `version !== 'v1'` or `iv`/`tag` falsy or `body === undefined`. GCM failure throws Node's raw crypto error (no custom text). No IV/tag length check of its own.
- `wrapWithPassword(dataKey, password, kdf = DEFAULT_KDF)` (61-65): salt = 16 random bytes; `wrappedKey = seal(kek, dataKey.toString('base64'), WRAP_CONTEXT)` (the wrapped plaintext is the BASE64 TEXT of the 32-byte key); returns `{ salt: b64(salt), kdf, wrappedKey }`.
- `unwrapWithPassword(wrap, password)` (68-75): derive (outside try; derive errors propagate raw), then `open(...)` in try/catch: ANY failure after derivation, including a malformed `wrappedKey`, becomes `WrongPasswordError`. Returns `Buffer.from(plain, 'base64')`.
- `newDataKey()` (77-79): `randomBytes(32)`.
- Contexts live in rt: `providerContext(id) = 'provider-key:' + id` (rt:52), `exchangeContext(id) = 'okx-credentials:' + id` (rt:53), `PASSWORD_WRAP_ID = 'password'` (rt:51).

### 1.3 Methods (rt:641-721)

- `enableVault(password)` (rt:642-655), in `exclusive`: status must be `OFF` else `Error('A master password is already set')`. New data key; `wrapWithPassword(dataKey, password, this.kdf)`; ONE transaction: `saveVaultKey('password','PASSWORD',wrap)` then, for every `getProviderKeys()` entry, `saveSealedProviderKey(id, seal(dataKey,key,providerContext(id)))` (that store method also deletes the plaintext row). After the transaction `store.scrub()` (rt:651); then `this.dataKey = dataKey`; invalidate `vault, providers, exchange`. `this.keys` is NOT cleared. Exchange sessions untouched.
- `unlock(password)` (rt:661-687), in `exclusive`: status must be `LOCKED` else `Error('MochiPrep is not locked')`. `dataKey = openVault(password)` (wrong -> `WrongPasswordError`, status stays LOCKED). Decrypts ALL `getSealedProviderKeys()` before assigning (a corrupt row throws a raw crypto error and leaves it LOCKED). Sets `dataKey`, fills `keys`, invalidates `vault, providers, exchange`, then the OKX reconnect loop (1.4). Returns `{ failed: string[] }` (account NAMES).
- `changePassword(current, next)` (rt:689-694), in `exclusive`: `dataKey = openVault(current)` (works whether LOCKED or UNLOCKED; OFF -> `No master password is set`; wrong -> `WrongPasswordError`); `saveVaultKey('password','PASSWORD', wrap(dataKey,next))` (upsert on id; `created_at` kept, store:496-501). No scrub, no invalidate, `this.dataKey` unchanged.
- `disableVault(password)` (rt:697-709), in `exclusive`: `openVault(password)` (no status check beyond that: works LOCKED or UNLOCKED); decrypts all sealed provider keys; ONE transaction: `saveProviderKey(id,key)` each, then `store.deleteVault()` (deletes `sealed_exchange_credentials`, `sealed_provider_keys`, `vault_keys`, store:503-507). Then `keys.set` each, `dataKey = null`, invalidate `vault, providers, exchange`. NO `scrub()`. Connected exchange sessions stay connected. Comment: saved OKX credentials are deleted since they never exist in plaintext.
- `resetVault(confirmation)` (rt:712-721), NOT async. Check order: (1) `confirmation !== VAULT_RESET_PHRASE` -> `Error('Type exactly: DELETE SAVED KEYS')`; (2) `vaultBusy` -> `Another master password action is in progress`; (3) status OFF -> `Error('No master password is set')`. Then collects sealed provider ids, `transaction(deleteVault)`, `keys.delete(id)` for them, `dataKey = null`, invalidate `vault, providers, exchange`. No scrub. Sessions stay in memory.
- `setKey(providerId, key)` (rt:579-586): LOCKED -> `Error('Unlock MochiPrep with your master password first')`; UNLOCKED -> `saveSealedProviderKey(id, seal(dataKey, key, providerContext(id)))`; OFF -> `saveProviderKey` (plaintext). Then `keys.set`, invalidate `providers`. No scrub call (the test calls `runtime.store.scrub()` itself, okxtest:1217).
- `clearKey(providerId)` (rt:588-592): `store.deleteProviderKey` deletes from BOTH `provider_keys` and `sealed_provider_keys` (store:471-474); `keys.delete`; invalidate `providers`. `deleteProvider` (rt:594-599): DB cascade removes both key tables.
- `providerFor(config)` (rt:571-577): MOCK -> mock; no key and LOCKED -> `ProviderError('NO_KEY', 'Unlock MochiPrep with your master password to load the key for "<name>".')`; no key otherwise -> `No API key saved for "<name>". Enter it in Settings.`
- `providerViews()` (rt:941-948): `hasKey = MOCK || keys.has(id)`.
- `store.scrub()` (store:187-189): `if (txDepth === 0) db.exec('PRAGMA wal_checkpoint(TRUNCATE)')`; busy flag ignored. Node calls it ONLY in `enableVault` (rt:651); tests also call it (okxtest:1217, 1233).

### 1.4 Unlock's OKX reconnect and the `failed` list (rt:670-685)

For each `store.listSealedExchangeCredentials()` row `{accountId, sealed}`:
- `account = store.getAccount(accountId)`; `if (!account || this.exchanges.has(accountId)) continue;` (skipped, NOT added to `failed`).
- try: `saved = JSON.parse(open(dataKey, sealed, exchangeContext(accountId)))`; `await this.connectOkx({ ...saved, name: account.name, limits: account.liveLimits ?? DEFAULT_LIVE_LIMITS, remember: true }, accountId)`. `saved` holds `apiKey, secretKey, passphrase, environment`.
- catch: `failed.push(account.name)` and toast `{ type:'toast', level:'error', message: ``${account.name}: could not reconnect to OKX. ${this.redact(error.message)}`` }`.
- A reconnect never arms a real account (connectOkx sets `armed = venue === 'OKX_DEMO'`). The loop runs inside `exclusive`, sequentially, so unlock's HTTP answer waits for every OKX connect (each request has an 8 s timeout).
- Tests: okxtest:1225-1241 (reconnects, `armed:false`), 1243-1253 (withdraw key -> `failed == ['OKX']`, status still UNLOCKED).
